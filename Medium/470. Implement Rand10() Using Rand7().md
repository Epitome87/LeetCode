# [470. Implement Rand10() Using Rand7()](https://leetcode.com/problems/implement-rand10-using-rand7)

## Description

Given the **API** `rand7()` that generates a uniform random integer in the range `[1, 7]`, write a function `rand10()` that generates a uniform random integer in the range `[1, 10]`. You can only call the API `rand7()`, and you shouldn't call any other API. Please **do not** use a language's built-in random API.

Each test case will have one **internal** argument `n`, the number of times that your implemented function `rand10()` will be called while testing. Note that this is **not an argument** passed to `rand10()`.

**Example 1:**

**Input:** n = 1  
**Output:** [2]

**Example 2:**

**Input:** n = 2  
**Output:** [2,8]

**Example 3:**

**Input:** n = 3  
**Output:** [3,8,10]

**Constraints:**

- `1 <= n <= 10^5`

**Follow up:**

- What is the [expected value](https://en.wikipedia.org/wiki/Expected_value) for the number of calls to `rand7()` function?
- Could you minimize the number of calls to `rand7()`?

## My Solution

**JavaScript**

```js
// Approach: Rejection Sampling. If we call rand7() once, we generate [1, 7]. If we call it again, we get
// another range from [1, 7], which we pair against each of those previous numbers in the same range.
// This gives 7 * 7 = 49 possible options with equal probability. But we want 10 options. We cannot
// simply mod 49 by 10, because that will leave us with 1 option that is not possible (50) and thus
// not equal probabilities. To fix this, we re-iterate until our two calls to rand7() generate a number
// in the range [0, 39] (40 values), thus discarding values outside of that range. We finally return the
// result of those two rand7() calls in a way that forces its range to [1, 10].
const rand10 = () => {
  let num = 40;

  while (num > 39) {
    num = (rand7() - 1) * 7 + (rand7() - 1);
  }

  return (num % 10) + 1;
};
```

| Time Complexity | Space Complexity |
| --------------- | ---------------- |
| O(1)            | O(1)             |
